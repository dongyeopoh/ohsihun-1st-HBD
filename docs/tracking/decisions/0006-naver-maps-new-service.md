# 0006. 지도를 신규 네이버 Maps로 교체한다

날짜: 2026-10-26

## 상황

공개 사이트의 지도가 뜨지 않게 되었다. `index.html`이 불러오던 구 `ncpClientId` 방식의 네이버 지도 스크립트가 인증에 실패해 지도 영역이 빈 상자로만 남았고, 오시는 길 섹션의 핵심인 지도가 방문자에게 보이지 않는 상태였다. 보호자는 이미 네이버 클라우드 플랫폼에서 신규 Maps 키를 발급받아 두었고, 그 키가 속한 Application에 배포 주소와 로컬 개발 주소를 등록해 두었다.

## 결정

신규 네이버 Maps로 바꾼다. 구체적으로 세 가지다.

- 키 교체: `index.html`의 지도 스크립트를 `https://oapi.map.naver.com/openapi/v3/maps.js?ncpKeyId=2965gcgzan`으로 바꾼다. 로드 방식은 지금처럼 헤드에서 동기 로드다.
- 인증 실패 기록: 지도 스크립트보다 앞에 `window.navermap_authFailure`를 정의해, 인증에 실패하면 브라우저 콘솔에 오류 한 줄(키 오류 또는 서비스 URL 미등록)을 남긴다. 화면에는 여전히 아무것도 띄우지 않는다.
- 개발 모드 정리: `Location`의 지도 생성 effect에 `map.destroy()`를 호출하는 정리 함수를 추가해, 개발 모드 `StrictMode`에서 같은 div에 지도가 두 번 만들어지던 것을 없앤다.

지도의 모양과 동작(좌표, 줌 18, 컨트롤 위치, 마커, 처음부터 열린 정보창)은 바꾸지 않는다.

## 검토한 대안

- 카카오맵: 계정과 키를 새로 만들어야 하고, 지도 모양과 API 호출 코드가 모두 바뀐다.
- 구글 지도: 결제 수단 등록이 필요하고, 국내 상세도가 낮다.
- 오픈스트리트맵(Leaflet 등): 지도 라이브러리를 새로 설치해야 하고(런타임 의존성 추가 금지 규칙과 충돌), 국내 상세도가 낮다.

보호자가 이미 신규 Maps 키를 발급받았고, 코드 변경이 스크립트 주소 한 줄 수준으로 가장 작으며, 지도 모양이 그대로이므로 네이버를 택했다.

## 결과

- 키는 보호자의 다른 사이트와 공유되는 Application에 속한다. 키를 회전·폐기하면 그 사이트에도 함께 영향이 간다. 그 사이트의 이름·주소는 저장소에 적지 않는다.
- 로컬에서 지도를 확인할 수 있는 주소는 등록된 포트 5173(`http://localhost:5173/ohsihun-1st-HBD/`)뿐이다. 다른 포트에서는 인증 실패 메시지가 콘솔에 찍히고 지도가 비어 보이지만 코드 문제가 아니다.
- 구 방식의 키 값과 호스트명은 코드·빌드 결과물·문서 어디에도 남기지 않는다. 언급이 필요하면 "구 `ncpClientId` 방식"이라고만 쓴다.
- 이 변경은 다른 정리 작업(글꼴 정리, 매니페스트 수정, 사진 메타데이터 등)과 묶지 않고 단독 커밋으로 먼저 배포한다. 공개 사이트의 지도가 깨져 있어 복구가 급했고, 지도만 바꾼 커밋은 문제가 생겼을 때 되돌리기도 쉽기 때문이다. 이 때문에 git 규칙에 "중간 커밋에 `dist/`가 옛 상태일 수 있으며 배포는 `dist/`가 최신인 커밋에서만 한다"는 예외를 추가했다.
