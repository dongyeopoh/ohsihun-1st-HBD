# 0002. 소스와 빌드 결과물을 `main` 한 브랜치에 함께 커밋한다

날짜: 2026-10-20

## 상황

지금까지 로컬 `main`에는 빌드 결과물(`dist/`)만 11개 커밋으로 쌓여 있고, 소스 코드는 한 번도 커밋되지 않았다. 원격에는 `gh-pages` 브랜치만 있다. 소스 변경 이력이 없어서 어떤 커밋이 어떤 코드 변경에서 나왔는지 추적할 수 없고, 작업 폴더가 사라지면 소스를 복구할 길이 없다.

## 결정

`main`에 소스와 `dist/`를 모두 커밋한다. 배포는 기존대로 `git subtree push --prefix dist origin gh-pages`로 한다. 원격에 `main`을 새로 올린다.

## 검토한 대안

- 소스는 커밋하지 않고 현재 방식 유지: 이력이 없는 상태가 계속된다. 보호자가 거절했다.
- 소스 전용 브랜치와 배포 브랜치 분리(`dist/`를 추적하지 않고 CI가 빌드·배포): 저장소가 깔끔해지지만 GitHub Actions 설정이 추가되고, 보존 단계인 프로젝트에 자동화 인프라를 새로 들이는 비용이 더 크다.

## 결과

- 소스 변경과 그 빌드 결과물은 같은 커밋에 들어간다. `dist/`가 `.gitignore`에 있으므로 `git add -f dist`가 필요하다.
- 커밋마다 번들 파일 diff가 커진다. 이는 감수한다.
- `gh-pages`에 직접 커밋하는 길은 막힌다. 모든 배포는 `main`에서 subtree push로만 한다.
